# خطة عمل: تدقيق قاعدة بيانات MySQL وربطها الكامل مع هوستنجر (Hostinger)

## الملخص التنفيذي
تهدف هذه الخطة إلى مراجعة وتدقيق كامل قاعدة بيانات المشروع، وتوحيد ملفات الـ SQL الاحتياطية في ملف رئيسي معتمد وجاهز للاستيراد في لوحة تحكم هوستنجر (phpMyAdmin) بدون أي أخطاء، مع ضبط خادم التطبيق (Node.js/Express) وواجهة المستخدم (React) لضمان حفظ كل عملية تسجيل، تعديل، وإضافة أعضاء مباشرة في قاعدة بيانات MySQL، وإنهاء أي اعتماد على التخزين المحلي المؤقت (LocalStorage).

---

## 1. القرارات المؤكدة (بناءً على إجاباتك)
1. **طريقة المزامنة**: وضع السيرفر المباشر مع توجيه وحفظ كافة العمليات مباشرة في قاعدة بيانات MySQL على هوستنجر.
2. **ملف الـ SQL المعتمد**: إنشاء ملف SQL موحد وشامل للهيكل وكافة الأعمدة والجداول مع بيانات تجريبية وحسابات إدارة جاهزة للاستيراد بضغطة زر واحدة.
3. **تشفير كلمات المرور**: استخدام تشفير قياسي آمن (Standard SHA256 / bcrypt) متوافق تماماً مع بيئة Node.js والـ PHP في هوستنجر.

---

## 2. المعمارية التقنية وتدفق البيانات

```
[ متصفح المستخدم / المشرف ]
            │
            ▼  (طلبات HTTP / JSON عبر Fetch API)
[ واجهة React: التسجيل / تعديل العضو / إضافة عضو ]
            │
            ▼  (مسارات API: /api/auth/register, /api/members, /api/admin/...)
[ خادم Node.js / Express (server.ts) ]
            │
            ▼  (اتصال موثق ومشفّر عبر مكتبة mysql2)
[ قاعدة بيانات هوستنجر MySQL / phpMyAdmin ]
    - جدول members (جميع الأعمدة الـ 35+ بالكامل)
    - جدول admins (حساب الإدارة مع الصلاحيات)
    - جدول plans, requests, journeys, audit_logs
```

---

## 3. تفاصيل خطوات التنفيذ (Phase 3)

### الخطوة 1: توحيد وإنتاج ملف SQL رئيسي معتمد لهوستنجر
- **المشكلة الحالية**: ملف `tawafok_database_hostinger_ready.sql` ينقصه أعمدة هامة مثل (`nickname`, `real_name`, `whatsapp`, `district`, `tribe`, `ethnicity`, `ethnicity_other`, `partner_specifications`, `details`).
- **الحل**:
  - إنشاء ملف SQL موحد ورسمي: `database_backup/hostinger_master_database.sql` ونسخه إلى جذر المشروع لسهولة الوصول.
  - تعريف جميع الجداول بنظام ترميز `utf8mb4_unicode_ci` لدعم اللغة العربية والرموز بشكل مثالي.
  - إضافة كافة القيود (Foreign Keys)، الفهارس (Indexes)، والبيانات الأولية (حساب المشرف، الباقات، وبيانات تجريبية لأعضاء من الجنسين).
  - كتابة تعليقات وإرشادات واضحة للاستيراد في phpMyAdmin دون ظهور أخطاء `Duplicate column` أو `Table doesn't exist`.

### الخطوة 2: مراجعة وضبط مسارات الخادم (`server.ts`)
- تدقيق مسارات التسجيل وإدارة الأعضاء:
  - `/api/auth/register`: التأكد من استقبال وتخزين كافة الحقول الشخصية وحقول المواصفات والشريك بدقة في جدول `members`.
  - `/api/members` (POST): ربط زر "إضافة عضو" في لوحة الإدارة ليقوم بحفظ العضو مباشرة في MySQL مع توليد معرف فريد وتشفير كلمة المرور.
  - `/api/members/:id` (PUT): ضمان حفظ أي تعديل في بيانات العضو أو حالته مباشرة في القاعدة.
  - إرجاع استجابات خطأ واضحة ومفصلة في حال حدوث نقص في الاتصال، لتجنب الإيهام بنجاح العملية دون حفظ فعلي.

### الخطوة 3: تحديث الواجهة الأمامية (`AppContext.tsx` و `AdminAddMemberModal.tsx`)
- ربط دالة `handleAddMember` و `updateMember` في سياق التطبيق بإرسال طلبات حقيقية للخادم واستقبال النتيجة المحدثة من قاعدة البيانات.
- التأكد من إظهار تنبيهات نجاح/فشل حقيقية للمشرف والمستخدم عند التسجيل أو الإضافة.
- إزالة الاعتماد على حفظ البيانات في `localStorage` فقط ليكون التخزين الرئيسي في قاعدة البيانات المركزية.

### الخطوة 4: ملف البيئة والإرشادات (`.env.example` و `DEPLOYMENT_GUIDE.md`)
- توثيق متغيرات الاتصال بهوستنجر بشكل واضح:
  ```env
  DB_HOST=localhost
  DB_PORT=3306
  DB_USER=u123456789_tawafok
  DB_PASSWORD=your_strong_password
  DB_NAME=u123456789_tawafok_db
  PORT=3000
  ```
- إضافة دليل خطوات عملي وسريع باللغة العربية يشرح كيفية:
  1. إنشاء قاعدة البيانات ومستخدمها في هوستنجر.
  2. استيراد ملف الـ SQL بنقرة واحدة في phpMyAdmin.
  3. ربط المشروع وتشغيله على هوستنجر بنجاح.

## 4. خطة التحقق والاختبار (Verification Plan)
1. **فحص بناء الكود والأنماط**: تشغيل `compile_applet` و `lint_applet` للتأكد من عدم وجود أي خطأ برمجي أو استيرادات مفقودة.
2. **محاكاة الاستيراد**: فحص سلامة بناء جمل SQL وصيغ الـ CREATE TABLE والـ INSERT لضمان خلوها من أي أخطاء نحوية تقبلها محركات MySQL 8.0+.
3. **اختبار تدفق البيانات**: التأكد من تطابق أسماء الحقول المرسلة من `AdminAddMemberModal` و `Register` مع الأعمدة المعرفة في SQL والخادم.
